System / research view

How It Works

From customer evidence to a timely purchase decision. This view explains the logic behind the customer experience — it is a prototype of the product logic, not a research dashboard.

Evidence-to-insight pipeline
Customer reviewsProduct-linked review text is the only input considered.
AI review analysisReview text is checked for wording tied to known shopper concerns.
Theme extractionRecurring dimensions (material, fit, comfort, appearance, quality) are grouped.
Evidence & sentimentEach theme is scored positive, negative, or mixed from the matched reviews.
Insight generationThe LLM must reach an 85% directional consensus from a minimum of 15 reviews.
Nudge eligibilityAt least one strong, evidence-backed theme must exist for this product.
Notification guardrailsOne nudge per product per 24h; the same insight is never repeated.
Customer insightA concise summary is shown with the source reviews underneath.
Prototype implementation: To simulate the LLM extraction locally without API costs, this prototype uses deterministic regex theme matching. In production, this is replaced by the LLM 85% consensus model defined in the case study. No AI service is currently powering this prototype; "Fit-Match Insights" is the product-facing concept name for this mechanism.
Guardrails: App-level complaints never become product claims. Mixed evidence stays visible. The Discovery Engine that surfaced the underlying barrier taxonomy is a separate, frozen research artifact — this MVP consumes its findings but does not modify it.
